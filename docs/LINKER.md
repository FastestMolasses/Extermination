# Extermination — Partial-Link Pipeline

Documents the `mwldmips`-based partial-link pipeline that produces
`elf/SCUS_971.12.elf` from all 3149 boot-ELF functions.

_Last updated: 2026-05-23_

---

## Purpose

The partial-link pipeline links the entire boot ELF from:
- Compiled `build/obj/*.o` files (matched decompiled C)
- Assembled `build/filler/*.o` files (splat-disassembled originals for
  every unmatched function)

The output `elf/SCUS_971.12.elf` should be byte-identical to the original
`config/SCUS_971.12` once all 3149 functions are matched.  Until then, a diff
report shows how many bytes match and where the first divergence is.

## How to run

Inside the `exterm-toolchain` container (repo bind-mounted at `/work`):

```sh
# Full pipeline: fill filler objects + generate LCF + link + compare
python3 tools/decomp/link.py

# Incremental (skip fill_unmatched — reuse existing build/filler/):
python3 tools/decomp/link.py --no-fill

# Generate LCF + object list but don't invoke the linker:
python3 tools/decomp/link.py --dry-run

# From the host via Apple container CLI:
container run --rm -v "$PWD:/work" -w /work exterm-toolchain \
    python3 tools/decomp/link.py
```

Fill filler objects only (useful for debugging assembly):
```sh
python3 tools/decomp/fill_unmatched.py [--jobs N] [--clean]
```

## Key files

| File | Role |
|---|---|
| `tools/decomp/link.py` | Main orchestrator: generates LCF, object list, invokes mwldmips, compares ELF |
| `tools/decomp/fill_unmatched.py` | Builds `build/filler/*.o` for all 3149 functions |
| `tools/decomp/strip_sections.py` | Post-processes GNU-as objects for mwldmips compatibility |
| `config/SCUS_971.12.lcf` | Metrowerks linker command file (generated by link.py; do not edit by hand) |
| `build/link_objects.txt` | Full paths to all 3149 `build/filler/*.o` objects (generated) |
| `elf/SCUS_971.12.elf` | Output linked ELF (generated; git-ignored — disc-derived material) |

## The linker: mwldmips

`mwldmips.exe` is the period-correct Metrowerks CodeWarrior PS2 linker (same
toolchain as `mwccmips.exe`).  It is a 32-bit Windows PE and runs under
`qemu-i386 wibo32` inside the container.

Invocation:
```sh
qemu-i386 tools/bin/wibo32 tools/mwccps2/mwldmips.exe \
    -map -nostdlib -m _start -nodead \
    -o elf/SCUS_971.12.elf \
    config/SCUS_971.12.lcf \
    @build/link_objects.txt
```

Flags:
- `-map` — generate `elf/SCUS_971.12.elf.xMAP` (symbol address map, useful for debugging)
- `-nostdlib` — no CodeWarrior runtime; the game has its own crt0
- `-m _start` — entry-point symbol
- `-nodead` — keep all sections even if not reachable from `_start`

## The LCF

`config/SCUS_971.12.lcf` is generated by `link.py`.  Key structure:

```
MEMORY
{
    main (RWX) : ORIGIN = 0x00100000, LENGTH = 0
    ...
}

SECTIONS
{
    # 2000+ absolute symbol definitions for BSS, IOP, HW registers:
    D_00275B00 = 0x00275B00;
    D_AC2D80   = 0x00AC2D80;
    ...
    _gp        = 0x0027D370;   # fixed by crt0

    .main :
    {
        # All 3149 functions in vram order — NO alignment directives here.
        # Any ALIGN() or ALIGNALL() causes mwldmips to pad before the first
        # function, shifting all vram addresses.
        func_00100000.o (.text)
        func_00100004.o (.text)
        _start.o (.text)
        ...

        # Data/rodata/sdata/BSS with ALIGN(0x80) between each section.
        *  (.data)
        *  (.rodata)
        ...
        LITERAL
        *  (.sdata)
        *  (.bss)
    } > main
}
```

**No ALIGN/ALIGNALL at the text-section start** — the original binary has
functions at 4-byte boundaries only.  Adding any alignment directive causes
mwldmips to insert padding words before `func_00100000`, shifting everything.

## Absolute symbol definitions

All `D_XXXXXXXX` and out-of-range `func_XXXXXXXX` symbols are defined as
absolute values in the LCF SECTIONS block.  This covers:
- BSS variables (addresses 0x00275xxx..0x00289xxx)
- IOP RAM accesses (0x00AC2D80, etc.)
- EE hardware registers (0x1F00000, etc.)
- EE kernel exception vectors (func_00000008, func_0000000C, etc.)

Addresses are derived from the `D_XXXXXXXX` / `func_XXXXXXXX` naming
convention (splat encodes the vram address in the symbol name).

## fill_unmatched.py — special cases

Several special cases are encoded in `fill_unmatched.py`:

### GPREL_FORCE_ASM (111 functions)

Functions that have a compiled `build/obj/*.o` but whose mwcc-compiled object
uses `R_MIPS_GPREL16` relocations that overflow at link time.  These are
force-assembled from the splat `.s` instead (the `.s` uses `%gp_rel()` which
becomes inline-patched by `strip_sections.py`).

### CROSS_LABEL_FUNCS (4 functions)

`func_00140004`, `func_001C2FF0`, `func_00200004`, `func_00201000` contain
`.L` labels that are referenced by branches in OTHER functions' `.s` files.
These are assembled with `-L` (keep local labels in symbol table), then all
`.L*` labels are globalized with `objcopy --globalize-symbol` so the linker
can resolve the cross-function references.

### WEAKEN_SYMBOLS

`func_00271DF8.s` defines `dlabel D_00275670` as a strong symbol in `.text`.
`src/func_001D2580.c` also declares `D_00275670` as a BSS global.  The filler
object has `D_00275670` weakened with `objcopy --weaken-symbol` to avoid a
multiply-defined error.

## strip_sections.py — post-processing

Called after every assembly (and after copying from `build/obj/`).  Applies
four fixes:

1. **Section removal** — strips `.pdr`, `.MIPS.abiflags`, `.reginfo`,
   `.gnu.attributes` (GNU-as extensions mwldmips doesn't understand), and any
   empty `.text`/`.data`/`.bss` (mwldmips rejects them).

2. **`.text` alignment** — GNU-as with `-march=r5900` emits `.text` with
   16-byte alignment (MIPS EE ABI default).  mwldmips pads between sections to
   satisfy alignment, inserting up to 12 bytes of zeros between consecutive
   functions.  `objcopy --set-section-alignment .text=4` forces 4-byte alignment
   so no padding is inserted.

3. **GPREL16 pre-application** — splat disassembles `lw $x, sym($gp)` as
   `addiu $x, $gp, %gp_rel(sym)`.  GNU-as emits `R_MIPS_GPREL16` for these.
   mwldmips applies GPREL16 only to actual `.sdata` symbols, not absolute
   symbols from the LCF.  We pre-apply the relocations in Python:
   `offset = sym_addr - 0x0027D370`, patch the instruction word, then remove
   the GPREL16 entry from `.rel.text`.

4. **No-op on mwcc compiled objects** — mwcc objects have 4-byte `.text`
   alignment and no GNU-as sections, so steps 1–3 are no-ops for them.

## Debugging tips

- **Map file**: `elf/SCUS_971.12.elf.xMAP` (generated by `-map`) lists every
  symbol with its linked address.  Use it to check where a function landed vs
  where it should be.

- **Compare loadable region**:
  ```python
  python3 -c "
  import struct
  def get_load(p):
      d = open(p,'rb').read()
      off = struct.unpack_from('<I',d,0x1c)[0]
      return struct.unpack_from('<I',d,off+4)[0], struct.unpack_from('<I',d,off+16)[0]
  "
  ```

- **Check GPREL16 in a filler object**:
  `mipsel-linux-gnu-readelf -r build/filler/FUNCNAME.o | grep GPREL`
  After `strip_sections.py` runs, there should be no GPREL16 entries.

- **Check .text alignment**:
  `mipsel-linux-gnu-readelf -S build/filler/FUNCNAME.o | grep text`
  The last column (Al) should be 4, not 16.

- **Re-run just the linker** (after editing LCF by hand for experiments):
  ```sh
  container run --rm -v "$PWD:/work" -w /work exterm-toolchain \
      qemu-i386 tools/bin/wibo32 tools/mwccps2/mwldmips.exe \
      -map -nostdlib -m _start -nodead \
      -o elf/SCUS_971.12.elf config/SCUS_971.12.lcf @build/link_objects.txt
  ```

## Known issues / future work

- **Multiply-defined symbols**: as more functions are decompiled, new multiply-
  defined conflicts may appear.  Add the conflicting assembly object to
  `WEAKEN_SYMBOLS` in `fill_unmatched.py`.

- **New GPREL16 force-asm functions**: if new mwcc-compiled objects have GPREL16
  overflow, add them to `GPREL_FORCE_ASM` in `fill_unmatched.py`.  Re-run with
  `--clean` to force rebuild of those objects.

- **Cross-function local labels**: if the linker reports `undefined: .L00XXXXXX`,
  find which `.s` file defines that label, and add the containing function to
  `CROSS_LABEL_FUNCS` in `fill_unmatched.py`.

- **PCSX2 verification**: once byte identity is high enough, test in PCSX2
  whether the linked ELF boots the game.  Requires manually replacing the boot
  ELF in a disc image.
